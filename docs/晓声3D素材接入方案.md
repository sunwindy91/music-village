## 3. 交互变体 → 关卡事件映射（DoD ③）

### 3.1 设计原则

1. **形态决定族，姿态在族内选图**。缺姿态 → 回落本族待机，**绝不跨族**。
2. 铁律「没有答错只有再试一次」：答错/卡关用 **安抚/好奇**，不用沮丧、哭泣、破碎。
3. 同一事件在不同成长阶段换图，孩子能感到「晓声陪我一起长大」。
4. 姿态是**短暂覆盖**（约 1.2–1.8s）后回到本形态待机；通关页 `celebrate` 可 sticky 到离开该视图。

## 4. 比例与裁切规范（DoD ④）

### 4.1 与现行 `.xs-png` 的冲突（事实）

线上 `main_c20260812h.css` L285–292 注释已写「3D 竖版手办：完整显示不裁切」，现行规则是：

```text
.xs-png-wrap { max-width: 190px; }
.xs-png { height:auto; max-height:150px; max-width:100%; width:auto;
          border-radius:14px; box-shadow: 0 14px 34px rgba(56,94,74,.24); }
```

**没有 `object-fit`。** 历史版本（`main_c20260812b.css`～`g.css`）曾是 `width:100%` + `border-radius:50%`，等于把竖版手办塞进圆框——头脚被切。信封所说的 **cover 风险** 来自两类真实用法：

1. 若给 `.xs-png` 加 `width:100%; height:150px; object-fit:cover`（聚类封面 `app.js` L204/L270 就是 cover），竖版手办会被**左右或上下裁切**，花环/鹿角/踮脚最先丢。
2. 现行 `border-radius:14px` + 矩形 `box-shadow`：透明底 webp 的四角仍被切成圆角，脚下阴影被框成「卡片」，不像手办立在草地。

封面/理论卡继续 cover（横带构图，F-02 已规定主体在垂直中段）。**晓声角色图禁止 cover。**

### 4.2 资产规范（导演转 webp 时）

| 项 | 规范 |
|---|---|
| 画幅 | **竖版手办**，长边 **480px**（高 480，宽随原比例，常见约 320–400） |
| 背景 | rembg **透明底**；脚底可留淡接触阴影（生成时已有则保留） |
| 格式 | 线上 webp quality 84（与 `docs/晓声6阶段_3D立体化Prompt.md` 一条龙一致）；png 仅留档 |
| 安全区 | 角色全身距画布边缘 ≥6%；头顶叶/花/角、踮脚/蹄 **不可贴边** |
| 视觉重心 | 角色几何中心略偏下（约画布高 58–62%），保证 150px 高的槽里仍是「脚在下、脸在中上」 |
| 禁止 | 方形 1:1 强裁；纯白/纯黑大底留在成品里；图上烧字/水印 |

### 4.3 CSS 方案：`object-fit: contain` + 底对齐

建议替换 h 版 `.xs-png` / `.xs-png-wrap`（选择器不变，导演改 CSS 时按此写）：

```css
.xs-png-wrap {
  position: relative;
  width: 100%;
  max-width: 190px;
  height: 168px;              /* 比 150 略高，给竖版含角/叶 */
  margin: 0 auto;
  display: flex;
  align-items: flex-end;      /* 脚落地 */
  justify-content: center;
}
.xs-png {
  width: auto;
  height: auto;
  max-width: 100%;
  max-height: 100%;
  object-fit: contain;        /* 禁止 cover */
  object-position: center bottom;
  display: block;
  border-radius: 0;           /* 透明底不要圆角裁切 */
  box-shadow: none;           /* 矩形阴影会框住透明像素 */
  /* 形态发光继续用现有 [data-form] drop-shadow */
}
```

容器 168px 来源：现行 max-height 150 + 约 12% 给鹿角/花环，仍小于 wrap 的 190 宽，竖版 contain 不会左右溢出。

**视觉重心对齐检查（接入后人工 6 形态扫一眼）**：

- 各形态脚底应落在 wrap **同一条底边**（flex-end），不要一株悬空、一株贴底。
- 脸部大约在 wrap 垂直 35–50%（种子/小芽更居中，鹿因腿长脸更靠上——允许，不要用 cover 强行对齐脸）。
- `breathe` / `form-in` 只 scale，原点默认 center；若脚底抖动，改为 `transform-origin: center bottom`。

### 4.4 与 DESIGN 的对齐

- 发光继续用现有 `[data-form]` `drop-shadow`（alpha 已 ≤.9），不要再加霓虹。
- `prefers-reduced-motion`：关掉 `xsBreathe` / `xsFormIn` / `xs-burst`，姿态切图可瞬间换 src、不要放大旋转。
- 触控目标：晓声拖拽热区是 holder，不靠图片被 contain 后变小而缩小热区。

## 5. voice-core 姿态层接入设计（DoD ⑤）

### 5.1 最简可靠方案：形态定 base，姿态换 `img.src`（单图，不叠层）

**不要**第二张 img 做覆盖——3D 全身手办无法和另一姿势合成，叠了必穿帮。  
**不要**在 3D 图上叠 SVG 五官。

两层属性共存：

| 属性 | 谁写 | 含义 | 决定什么 |
|---|---|---|---|
| `data-form` | `applyGrowth`（已有） | 成长阶段 | **base 图**（FORMS）+ 形态发光 |
| `data-pose` | **新** `setPose` | 当前情绪 | **覆盖 src**；idle/空 = 用 base |
| `data-exp` | `setExpression` / mount `opts.exp` | SVG 遗产表情 | **仅 SVG 回退**生效 |

解析函数（伪代码，导演落笔时保持这个优先级）：

```text
resolveSrc(formKey, poseKey):
  form = FORMS by key（缺则 seed）
  pose = poseKey || 'idle'
  if pose == 'idle' or pose == null: return form.src
  variant = POSES[form.key][pose]      // 见 §3.2 展开表
  if variant missing: variant = POSES[form.key]['idle'] 或 form.src
  return variant
```

`POSES` 建议与 `FORMS` 同文件、同层常量。变体 src 例：

```text
POSES.sprout.happy     = 'assets/3d/3D山灵手办开心托腮.webp'
POSES.sprout.comfort   = 'assets/3d/3D山灵手办歪头捧脸.webp'
POSES.sprout.curious   = 'assets/3d/3D山灵手办好奇探头.webp'
POSES.sprout.celebrate = 'assets/3d/3D山灵手办开心拥抱.webp'
```

（其余按 §3.2 填满；缺键不要写 `undefined` 路径。）

### 5.2 `setPose` API（新增，与 `applyGrowth` 对称）

```text
setPose(pose, opts = {})
  pose: 'idle' | 'welcome' | 'happy' | 'think' | 'curious' | 'comfort' | 'celebrate'
  opts.holdMs  默认 1400；sticky 时忽略
  opts.sticky  true = 不自动回 idle（celebrate 页用）
```

行为对齐 `applyGrowth` 的探测模式（L249–262）：

1. `root.dataset.pose = pose`
2. `src = resolveSrc(root.dataset.form || 'seed', pose)`
3. `new Image()` 探测；onload 才改 `.xs-png.src`；onerror **保持当前图**（变体未上线也不 404 闪破图）
4. 非 sticky：`holdMs` 后 `setPose('idle')`；若其间又 `setPose`，清掉旧 timer（与 `stopTyping` 同一纪律）
5. 不碰 `dataset.form`，不触发 `form-in` / `burstParticles`（那些只属于成长）

`applyGrowth` 小改（行为契约）：

- 算完 `want` 之后：`src = resolveSrc(want.key, root.dataset.pose || 'idle')`，而不是无脑 `want.src`
- 若当前 pose 是短暂态（happy/comfort/…）且不 sticky：仍切到该姿态图，timer 结束后 idle 会落到**新形态**主体——跨阶通关时孩子先看到新身体的庆祝/答对，而不是旧身体跳一下再进化

### 5.3 与 SVG 表情共存

| 模式 | 条件 | 表情怎么做 |
|---|---|---|
| PNG 3D（默认） | `config.xsPng !== false` 且 img 未 error | **只换 3D 图**；`data-exp` 可继续写（无害），但 **去掉** h 版 L298–300 三条 `.xs-png-wrap[data-exp] transform`（倾斜/放大会扭曲已摆好的手办，且与 `breathe` 抢 transform） |
| SVG 回退 | pngTpl 的 `img.onerror`（L138–145） | 保持现有 `data-exp` 五官；`setPose` no-op（没有 `.xs-png`） |

`breathe` / `float` / `form-in` 保留在 PNG 上（整体呼吸，不是表情）。

可选薄封装：`setExpression('happy')` 在 PNG 模式内部转 `setPose('happy')`，减少 app.js 双调用。若做，映射为：`calm→idle`，`happy→happy`，`thinking→think`，`surprised→curious`，`encourage→comfort`。通关仍应显式 `setPose('celebrate')`（`happy` ≠ 跳跃拥抱）。

### 5.4 与 `mountXs` 的顺序（必守）

现行 `pngTpl` 总是种子 src。正确顺序：

```text
mountXs(id, { exp, pose, breathe, float })
  → VoiceCore.mount          // 种子图
  → applyGrowth(stageNum())  // data-form + base
  → setPose(pose || 'idle')  // 覆盖变体
```

建议把后两步收进 `app.js` 的 `mountXs`（一处修补，splash / map / stage / celebrate / staff 全受益）。**celebrate 漏 applyGrowth** 是现在就能看到的缺口，姿态层不修会一直庆祝种子。

### 5.5 导演执行切片（仍由导演改 src，本文件不改）

1. CSS：§4.3 contain + 取消角色图圆角阴影；删 PNG 的 `data-exp` transform。
2. `voice-core.js`：加 `POSES` + `setPose` + `resolveSrc`；`applyGrowth` 经 resolve；export `setPose`。
3. `app.js` `mountXs`：mount 后 `applyGrowth` + `setPose`。
4. 答题/stumble/quiz/drum/celebrate：在现有 `say` 旁加一行 `setPose`（§3.3 表）。
5. 冒烟：6 形态地图标签仍随点亮变；PNG 404 仍回 SVG；变体 404 不破图；`prefers-reduced-motion` 无放大旋转。

不改 `FORMS` 的 key/min/name/主体文件名。
