## 1. 产品一句话

> **给山区音乐零基础的孩子，一个 AI 陪伴的"乐理寻宝"游戏**——让抽象的音高、节奏、和弦，变成大山世界里看得见、摸得着、玩得懂的规则。

- 不是"教乐理的工具"，是"让孩子愿意打开、愿意坚持、感受到音乐美好的游戏"
- 核心机制：**乐理 = 世界的物理规则**（越高=音越高、越长的路=越长的音、三种颜色合体=和弦）

---

## 2. 用户与场景

| 项 | 内容 |
|----|------|
| 主用户 | 6-9 岁山区儿童（音乐零基础） |
| 场景 | 乡村学校课后 / 家庭手机平板 / 无音乐老师的替代 |
| 设备 | 手机 / 平板（纯网页，零安装，低配可跑） |
| 陪伴者 | 老师或家长可看"开发者模式"了解学习目标 |

**设计前提（儿童心理）**：
- 注意力短 → 每关 1-2 分钟，即时反馈
- 怕失败 → 没有"答错"，只有"再试一次"，永远有路可走
- 需要成就感 → 收集/点亮/勋章，进度永远可见
- 具身认知 → 先听先唱先动，再认符号

---

## 3. 核心体验循环（学习闭环）

```
        ┌─────────────────────────────────────────────┐
        │                                             ▼
  ① 观察（看小鸟飞）   ② 体验（自由玩）   ③ 挑战（小目标）   ④ 成就（点亮石碑）
  建立心智映射         试错无惩罚          目标驱动练习        庆祝 + 勋章 + 解锁
        ▲                                             │
        └───────────── 解锁下一张地图 / 下一关卡 ◄─────┘
```

**每个关卡 = 三件套**（乐理概念 × 心智模型 × 游戏动作）+ 判定规则 + 反馈协议 + 目标。

## 5. 画面流程（Screen Flow）与衔接逻辑

> 原则：**每个画面只做一件事**，衔接必须给出"为什么跳转"（孩子能懂的动机），禁止让小朋友自己找路。

### 画面0 · 启动
| 元素 | 说明 |
|------|------|
| 太阳升起 + 山峦渐现 | 3 秒内自然过渡，无加载条 |
| 山灵打招呼 | "早上好呀！大山在等我们呢" |

**衔接** → 点击任意处 / 自动 1.5s 进入地图。

### 画面1 · 大山地图（山路寻宝）
| 元素 | 说明 |
|------|------|
| 一条蜿蜒山路 | 从山脚小屋通向山顶，串起 5 个地点 |
| 5 个地点标记 | 声音山谷🏞️ / 音阶山谷⛰️ / 节奏小路🛤️ / 和弦花园🌸 / 旋律草原🌾 |
| 状态 | 🔒未开启 / ▶可出发(发光)/ ✓已探索(打勾) |
| 山灵 | 常驻提示："先去哪座山？" |

**衔接规则**：
- 点可出发地点 → 进入该地图关卡总览
- 点未开启 → 山灵说"要先点亮前面的石碑才能过去哦"（说明解锁动机）

### 画面2 · 关卡总览
| 元素 | 说明 |
|------|------|
| 关卡导航 chips | 本地图的关卡（观察→配对→…），完成打勾 |
| 山灵对话 | 介绍本关乐理点（孩子话） |

**衔接规则**：
- 点关卡 chip → 进入对应关卡舞台
- 关卡内完成 → 自动回到总览并打勾 + 山灵庆祝

### 画面3 · 关卡舞台（核心，含 3a-3e）
| 元素 | 说明 |
|------|------|
| 五线谱舞台 | 自然风（木色线 + 发光音符 + 小鸟） |
| 山灵对话 | 顶部常驻，实时反应 |
| 操作区 | 观察：播放/速度；配对：听音/再听 |
| 反馈 | 对→欢呼+光效；错→"再听一次"+逼近引导（高一点/低一点） |

**衔接规则**（状态机）：
- 观察完成（看完一遍）→ 山灵："看懂了就试试帮小鸟回家吧！" → 推荐切到配对关卡
- 配对：答对 ≥3 只 → 通关 → 画面4
- 连续 3 次错 → 山灵示范模式（模仿即算参与）→ 不卡死

### 画面4 · 成就反馈
| 元素 | 说明 |
|------|------|
| 勋章获得动画 | 弹出 + 发光 + 音效 |
| 积分飞入 | ⭐ 累计到顶栏 |
| 山灵庆祝 | "太棒了！石碑点亮啦！" |

**衔接规则**：
- 确认后 → 回关卡总览（打勾）
- 地图上该地点变 ✓ → 下一地点解锁提示

## 6. 交互设计规范（顺乎儿童心理）

1. **大目标区**：所有可点目标 ≥44px，热区大于视觉（透明包围）
2. **悬停反馈**：只发光/轻摇，**不位移**（SVG 位移会导致抖动+点不到——已踩坑修复）
3. **无"×"语言**：错 = "再听一次" + 逼近引导（高一点/低一点），绝不否定孩子
4. **过程有奖励**：每次尝试都攒正反馈，不是只有全对才开心
5. **进度永远可见**：积分/勋章/打勾/石碑，都在界面上
6. **一次一件事**：画面不堆信息，专业术语藏进"开发者模式"（⚙️）
7. **音效温柔**：三角波 + 缓起缓落，不刺耳（Web Audio 实现）
8. **容错先宽后严**：第一关宽松（容差大），随关卡收紧

## 7. 游戏机制规格（关卡模板 · 队友照填）

```js
{
  id: 'bird-home',
  type: 'point',        // observe观察 / point配对 / sort排序 / sing跟唱 / boss石碑
  title: '点小鸟回家',
  concept: '音高可以听出来，也能看出来',        // ①乐理概念（孩子话）
  model: '听音→联系位置→音高辨识',            // ②心智模型
  action: '听山灵唱的音，点对应的小鸟',        // ③游戏动作
  judge: '点对+10；错→再听+高/低提示',        // ④判定规则
  feedback: '对→欢呼+加分；3错→山灵示范',     // ⑤反馈协议
  goal: '帮3只小鸟回家（共5题）',             // ⑥目标（不是全对）
  notes: [60,62,64,67,69], rounds: 5, passCount: 3,
  guidance: ['山灵引导语…'],
}
```

**关卡类型 → 乐理点映射（路线图）**：
| 关卡类型 | 乐理点 | 地图 |
|---------|--------|------|
| observe 观察 | 音高=位置 | 音阶山谷 ✓ |
| point 配对 | 音高辨识 | 音阶山谷 ✓ |
| sort 排序 | 音阶=高低排列 | 音阶山谷（P1）|
| sing 跟唱 | 音准（同心圆）| 音阶山谷（P1）|
| tap 拍打 | 时值/节拍 | 节奏小路（P1）|
| collect 收集 | 三和弦=颜色合成 | 和弦花园（P1）|
| boss 石碑 | 综合成就 | 各地图终章 |

## 8. 视觉设计规范（大山主题 · Token）

| Token | 值 | 用途 |
|-------|-----|------|
| 天空 | `#aee1ff → #fff3dc` 渐变 | 清晨天空 |
| 森林绿 | `#3e7d5e` | 主色/按钮 |
| 阳光金 | `#ffd166` | 可点/奖励高亮 |
| 草莓粉 | `#e76f8a` | 听音/重点操作 |
| 泥土棕 | `#c98a5e` | 开发者模式/木头 |
| 卡片 | `#ffffff` 圆角24 柔和阴影 | 内容容器 |
| 字体 | 圆体（Baloo 2 / 雅黑） | 儿童友好 |

**签名元素**：山峦剪影 + 草地 + 云 + 太阳（自然层）· 山路虚线（寻宝感）· 发光音符（乐理感）。

## 9. 技术架构（接口契约 v1.0）

```
src/
├── index.html        合并点（大山主题 UI）
├── app.js            渲染/路由/关卡类型分派/积分
├── config.js         AI 开关（初赛关闭，决赛开启）
├── shared/levels.js  关卡模板（内容层·队友填）
└── modules/
    ├── audio/music-core.js   音频核心（Web Audio）
    └── voice/voice-core.js   山灵视觉/语音 + AI 对话预留
```

**数据流**：`MusicCore`(音频/判定) ⇄ 事件 ⇄ `VoiceCore`(山灵/视觉) → `app.js`(合并)

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 山区网络弱 | 纯前端 + localStorage，断网可玩 |
| 孩子怕错 | 无惩罚 + 逼近引导 + 示范模式 |
| 麦克风环境噪 | 初赛不做音准，决赛限定安静场景 |
| 儿童隐私 | 无账号零收集，纯本地 |
| 队友不懂乐理 | 三件套模板 + 本文档即"操作手册" |
