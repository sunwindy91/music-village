## 高

### 1. 作曲「变成五线谱」可被快速连点重复计分/存作品
- **位置**：`src/app.js` `runners.compose` → `toStaff`（约 L912–L933）
- **问题**：`pointerdown` 无防抖/`saving` 锁。连点两次会：`works.push` 两次、`addPoints(pointsPerCompose)` 两次；若都落在 `completed.compose` 置位前，还可能重复走「首通」成长。
- **建议修法**：函数入口加 `if (locking) return; locking = true;`，或按钮 `disabled=true` 直到 `openStaff` / say 结束；首通标记与写库放同一同步临界区。

### 2. 重复通关庆祝文案仍显示「积分 +50」，但未加分
- **位置**：`src/app.js` `celebrate`（约 L954–L969）
- **问题**：仅当 `!App.state.completed[lv.id]` 时 `addPoints`；但 `$('#celebrate-points').textContent = '积分 +' + C.pointsPerClear` **始终执行**。孩子重玩会以为又得分。
- **建议修法**：`firstClear` 分支显示加分；否则显示「再玩一次也真棒」或隐藏积分行。

### 3. `VoiceCore.stopTyping` 不清理 `onDone`，气泡 `finish` 可能在视图切换后仍回调
- **位置**：`voice-core.js` `say`/`finish`/`stopTyping`（约 L154–L184）；`app.js` `openLevel`（约 L264）`say(..., { done: () => startLevel(lv) })`；`stage-back`（约 L1067–L1073）只 `stopTyping` 不 `hideBubble`、不清 `onDone`
- **问题**：会话令牌能挡住多数 `alive()` 路径，但 `openLevel` 的 intro `done → startLevel` **本身不检查 view/session**。若未来有路径在 stopTyping 后仍触发 `finish`（或补完逻辑变更），会在地图页注入关卡 DOM。
- **建议修法**：`stopTyping`/`hideBubble` 增加 `onDone = null` 选项（或 `cancelSay()`）；`openLevel` 的 done 内加 `if (App.state.view !== 'stage') return;` 且比对 session。

## 中

### 4. 鼓关离开时未统一走 `_drumCleanup`
- **位置**：`app.js` `runners.drum`（约 L521 `_drumCleanup`）；`stage-back`（约 L1071 只 `removeEventListener`）；`startLevel`（约 L275）会调 cleanup
- **问题**：当前 `finish`/`onBeat` 有 `alive()`（session 失效）保护，**暂不致错庆祝**；但 `abandoned` 标志不置位，与 `startLevel` 路径不一致，后续若有人改 `alive` 条件易回归。
- **建议修法**：`stage-back` / `celebrate` / `openConcert` 统一 `if (MV._drumCleanup) MV._drumCleanup()`。

### 5. `VoiceCore.mount` 每次重建 DOM，错误回退路径再绑监听——单例状态可短暂指向旧节点
- **位置**：`voice-core.js` L127–L148
- **问题**：`mount` 无显式 `unmount`；PNG `error` 回调若晚到，可能写已经不是当前 holder 的节点（用户已切到地图/舞台）。概率低但存在。
- **建议修法**：`mount` 生成 `token`/`generation`；error/onload 回调比对 generation；或 `error` 前 `img.onload=null`。

### 6. `burstParticles` 的 `setTimeout(..., 1300)` 无取消
- **位置**：`voice-core.js` L228–L238
- **问题**：形态切换后立即 `mount` 清空 root 时，超时仍 `p.remove()`——通常无害；极端频繁切换产生无效 timer。
- **建议修法**：把 timer id 推进数组，`clear()`/`mount` 时一并 `clearTimeout`。

### 7. `applyGrowth` 用 `new Image()` 探测，无竞态序号
- **位置**：`voice-core.js` L240–L261
- **问题**：快速连通两关时，较慢的 `onload` 可能套用过期 `want`（虽有 `dataset.form !== want.key` 判断，仍可能跳形态）。
- **建议修法**：`let growthGen++`；onload 内比对 gen。

### 8. Splash 回归用户双 timer 进地图
- **位置**：`app.js` `bootSplash`（约 L114–L117）
- **问题**：`say(... done → setTimeout(go,700))` 与 `setTimeout(go, 2200)` 并行；`go` 有 `view !== 'splash'` 守卫，**功能上安全**，但仍可能双呼 `MusicCore.start`/欢迎音竞争。
- **建议修法**：单一超时或只保留一条路径。

### 9. 全局 `pointerdown` 无「按下滑动出界」取消；部分控件可能误触
- **位置**：各 `addEventListener('pointerdown', …)`（听辨/作曲等）
- **问题**：儿童手指滑动时，`pointerdown` 即触发，无法像 `click` 那样取消。`config.js` 的 Pointer 兼容层合理，但交互语义偏「按下即点」。
- **建议修法**：关键答题可改为 `pointerup` + 命中测试，或忽略 `pointerType` 滑动阈值。

### 10. `localStorage` 作品列表无上限
- **位置**：`app.js` `saveProgress` / `toStaff`（约 L40–L47, L921–L922）
- **问题**：隐私模式已 try/catch；但长期使用 `works` 膨胀可能导致 `QuotaExceededError`（catch 后静默丢存）。
- **建议修法**：保留最近 N 首（如 20）；超限提示「山谷收藏满了」。

## 低

### 11. `celebrate` 重玩时用 `grow.spark` 文案
- **位置**：`app.js` L966–L967
- **问题**：`spark` 语义是成长金光，重玩不一定触发成长，话术略漂。
- **建议**：重玩用 `celebrate.clear`；首通才 `grow.*`。

### 12. `openStaff`/`celebrate-next` 使用 `.onclick =` 覆盖
- **位置**：`app.js` L987, L1051–L1056
- **问题**：不会叠加泄漏，但与项目其它 `addEventListener` 风格不一；且丢失多监听扩展点。
- **建议**：统一 `addEventListener`，或先 `replaceWith(btn.cloneNode)` 去旧监听。

### 13. `MusicCore.playSequence`/`playRhythm` 与 UI `alive` 耦合靠会话令牌
- **位置**：`music-core.js` L132–L180；关卡内 `onBeat`/`onDone`
- **问题**：`stopAll`/`resetTransport` 可清调度（阶段返回有 `stopAll`）——好。建议在审查回归时断言：返回地图后 Transport 无残留 schedule（冒烟可加）。

### 14. `mountXs` 不剥离旧 `xs-breathe`/`xs-float` 以外的状态
- **位置**：`app.js` L82–L88
- **问题**：多次 mount 一般 OK；若 holder 复用 class 污染，概率低。
- **建议**：mount 前 `el.className = 'xs-holder …'` 重置。
